# Security Controls and NIST Cybersecurity Framework

---

# Executive Summary

This project demonstrates the application of cybersecurity governance through the implementation of three key security controls based on the NIST Cybersecurity Framework (NIST CSF). Each control is linked to practical security implementations performed during an enterprise network security laboratory.

The project demonstrates how governance frameworks support technical security controls used to protect enterprise systems against modern cyber threats.

---

# Project Objectives

The objectives of this project were to:

- Apply the NIST Cybersecurity Framework
- Identify suitable enterprise security controls
- Understand the threats each control mitigates
- Link governance principles to practical implementations
- Improve enterprise cybersecurity posture

---

# Planning and Research

The NIST Cybersecurity Framework (NIST CSF) was selected because it provides internationally recognised guidance for identifying, protecting, detecting, responding to, and recovering from cybersecurity incidents.

The framework was supported by:

- ISO/IEC 27001
- POPIA
- Cybercrimes Act 19 of 2020

---

# Security Control 1 – Access Control

## Framework Reference

NIST CSF PR.AC-1

## Description

Access control ensures that only authorised users are able to access organisational systems, devices and information resources.

## Threats Addressed

- Unauthorised access
- Privilege abuse
- Insider threats
- Credential misuse

## Practical Implementation

During the networking lab the following controls were implemented:

- VLAN segmentation
- SSH Version 2
- Device authentication
- Encrypted passwords

These controls reduced the attack surface by restricting administrative access to authorised users only.

---

# Security Control 2 – Continuous Monitoring

## Framework Reference

NIST CSF DE.CM-1

## Description

Continuous monitoring allows organisations to detect suspicious behaviour and security events as they occur.

## Threats Addressed

- Malware
- Network scanning
- Suspicious traffic
- Policy violations

## Practical Implementation

Monitoring technologies included:

- Syslog
- Snort IDS
- Wireshark traffic analysis

These tools enabled continuous visibility into network activity.

---

# Security Control 3 – Incident Response Planning

## Framework Reference

NIST CSF RS.RP-1

## Description

Incident response planning establishes procedures for identifying, containing and recovering from cybersecurity incidents.

## Threats Addressed

- Delayed incident response
- Business disruption
- Data loss
- Extended recovery time

## Practical Implementation

The PICERL incident response lifecycle was used to document the response process for a simulated security incident.

# Lessons Learned

This project demonstrated that governance frameworks are not merely compliance documents but practical tools that guide the implementation of technical security controls. Effective cybersecurity depends on aligning governance, monitoring, and incident response with secure technical configurations.

---

# Recommendations

Future improvements include:

- Implement Multi-Factor Authentication (MFA)
- Conduct regular security audits
- Perform vulnerability assessments
- Review security policies annually
- Expand IDS coverage
- Automate compliance reporting

---

# Conclusion

The project successfully demonstrated how cybersecurity governance frameworks can be translated into practical enterprise security controls. The implementation of access control, continuous monitoring, and incident response planning strengthened the overall security posture of the simulated enterprise network while aligning with recognised industry standards.
